Freiburg Tile Walkthrough

One 640 px OpenStreetMap tile of central Freiburg, taken through the legend-driven pipeline. The first tab is the baseline run. Each later tab is one change to the method: exactly what changed, how it was measured, and the result before and after.

Baseline: Opus reads the legend; Jev screens all 25 classes on the tile, then searches each screened-in class with a box-and-inpaint loop on 160 px sub-tiles.

The pipeline

  1. Read legend
    Opus returns labels and symbol boxes; code crops.
  2. Choose tile
    640 px window with the most classes.
  3. Screen
    Jev: is this symbol anywhere in the tile? (×2)
  4. Search loop
    Box, inpaint, ask again on 160 px sub-tiles (×8).
  5. Georeference
    Merge, convert to EPSG:3857, write GeoPackage.
  6. Score
    Match to render-diff truth within 7 px.

1Read the legend

The legend sheet is generated from openstreetmap-carto's own icons at map scale. Opus 5.5 gets it enlarged ×3 and returns JSON: each entry's label and the pixel box of its symbol. Code tightens each box to the symbol's non-background pixels and cuts it out of the sheet. Nothing is redrawn.

2Choose the tile

3Screen every class

The whole tile is shown once per class, enlarged ×2, with that class's legend symbol: 25 separate calls. Only classes scoring 0.5 or more go on to the search loop. The legend symbol is enlarged by the same factor and padded to Jev's 280 px minimum, so it keeps the map's scale.

class present in tileclass absentdashed line: threshold 0.5orange label: present but screened out

4Search loop

For each screened-in class, the tile is cut into 25 sub-tiles of 160 px (overlapping by 40 px), each enlarged ×8 to 1,280 px. A 14 px icon then appears at about 112 px, the size where the pilot found Jev's boxes reliable. Each call asks whether an instance is left and where one is. If yes, the box centre becomes a point and the box is inpainted from its surroundings. The sub-tile is then asked again. It stops below 0.5, or when the box lands on painted-out pixels.

Every class works on its own copy of the tile, so a symbol removed in one sub-tile is already gone when an overlapping sub-tile is searched.

What went wrong

8 of 20 false positivesLook-alike classes claim the same icon

Each class is searched on its own, so one icon can be claimed by another class. Statue fired on Artwork four times and on Bust once. Pharmacy fired on Doctor twice, and Taxi on Bus stop. → tested in Change 2.

2 of 20 false positivesThe same icon found twice

A Memorial and a Traffic signal were each detected twice, about 7 px apart. One point is matched and the other counts as a false positive. Duplicates are only merged within 4 px, which is less than an icon's width.

5 false positives ≈ 5 missesRight icon, 8–15 px off

The box landed off-centre on partial icons at sub-tile edges or between neighbours. With a 12 px tolerance F1 would be about 0.86.

3 of 6 ParkingA colour the legend doesn't show

All three missed Parking icons are the pale-blue private-parking variant. In each case Jev answered "not present" (P 0.16–0.31). The prompt says "same shape and colour".

7 of 18 Traffic signalsDense clusters

Signals around junctions sit about 12 px apart; boxes land between them, and inpainting one can clip its neighbour.

5 of 20 false positivesNothing there in the ground truth

Fitness station twice, Church twice, Traffic signals once, with no true icon of that class within 15 px. Box confidence was high on some (0.87–0.90).

2 classesScreened out

Bust (P = 0.44) and Shelter (P = 0.16) each had one icon and never reached the loop.

How it was measured

  
One tile gives only 25 yes/no labels, so both methods ran on 8 non-overlapping 640 px tiles of Freiburg centre: the baseline tile (tile 0) and 7 random tiles drawn with seed 17. That gives 200 class–tile pairs. A class is truly present in a tile if the render-diff ground truth has at least one of its icons there.

Caveats

  
    
    
  • 8 tiles, all in one dense city area. The rural area isn't included yet.
    • 
    
  • The tile-6 Doctor failure shows batching can drop a class that single calls catch. One case in 200 can't tell us how often this happens.
    •

    What this tells us
    
  
      
    
    • A single-symbol "is there one like this?" question is permissive. Two different figures in the same colour both pass, even though the prompt says "same shape and colour". The loop is a good candidate finder, but it doesn't settle the class.
      • 
    
    • A comparison between legend symbols settles it. With both symbols available as options, Jev never confused them: 0 of 26 icons swapped, with probabilities of 0.97–0.99 on the tile's detections. So the pipeline should look for candidates per class, then let a Choice among all legend symbols decide the class.
      • 
    
    • Screening missed Dance (P = 0.42 with 2 Dance icons on the tile), the third present class screened out on this tile after Bust and Shelter. The screening threshold or prompt needs work.
      • 
    
    • A missing legend class looks like a hallucination. When the legend handed to the method is incomplete, its errors land on the nearest look-alike. On real maps with incomplete legends this will matter.
      • 
  
    

    

    
  
    Caveats
    
  
      
    
    • 26 icons area-wide and 8 detections on the tile: a clear result, but a small sample of one look-alike pair.
      • 
    
    • The Dance loop was forced on, past the screening result, so this tile's recall assumes screening worked.
      • 
    
    • The label "Fitness station" is too narrow: the same icon also marks gyms (fitness_centre). It was kept unchanged so that only one thing changed here.
      • 
    
    • One Dance icon was called "Charging station" in the 26-way question (but Dance in the two-way one), and one Fitness icon "none of these" in both.

      What this tells us
      
  
        
    
      • Names leak meaning into the yes/no search question. "Is there a Pharmacy here?" was answered yes on Doctor icons: same red-cross family, related meaning. A code made Jev rely on the picture, and wrong Pharmacy claims fell from 11 to 3. A sensible default is to search with codes.
        • 
    
      • Names can also mislead the class decision. On the 119-icon test, names produced 12 "Doctor / clinic → Hospital" answers (clinic is close in meaning to hospital); codes produced none.
        • 
    
      • But one Choice answer is noisy. Codes, in turn, sent 8 correct tile Doctors to "Museum" and lost more Pharmacies. Answers flipped between conditions on about a third of the icons. The class decision needs more than one look, such as a vote over two crops or two option orders, before the choice of names or codes for it can be settled.
        • 
    
      • Screening was unaffected (20 of 24 correct both ways).
        • 
  
      

      

      
  
      Caveats
      
  
        
    
      • Medical classes on 8 tiles and 119 icons in one city: three look-alike symbols, a small slice of the legend.
        • 
    
      • The loop detections differ between conditions, so the tile Choice check judges different crops in each. The 119-icon test is the like-for-like comparison.
        • 
    
      • "Doctor / clinic → Museum" appears under both conditions. It may be a quirk of how the red doctor's-bag icon compares with the museum's columned building at this size, and needs a look.
        • 
  
      

      

      



      

      
  
      
  
      
  
      

      

      
  
      Why
      
  
      Asking Jev the identical question 30 times showed it is not deterministic: on hard icons it gives the right class about 3 times in 4, and the wrong answers scatter across several classes. Right answers almost always come with a top probability near 1.00, while wrong ones are usually lower (median about 0.8), though about a quarter of wrong answers are still near 1.00. So a low-confidence answer is worth asking again, and a majority vote should pick the right class.
      

      

      
  
      What changed
      
  
      Only how many times the Choice question is asked, and how the answers are combined. The detections, crops, 31 legend options, names and prompt are exactly Change 5's. The repeated requests are byte-identical; the first call of each detection is Change 5's own stored answer.
