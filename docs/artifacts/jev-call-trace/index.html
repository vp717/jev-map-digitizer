Jev Call Trace

Every model call from the Freiburg single-tile run for three classes, shown as sent: the images, the prompt text and the raw answer, followed by what the pipeline did with it. The images here were rebuilt from the run's own code. The run was then replayed offline against the API cache, which only answers when each image's SHA-256 is identical to what was originally sent.

Anatomy of one Jev request

Each call sends one map image as state and attaches the legend excerpt as an asset. The excerpt is referenced inside the question text, where this page shows [legend image]. The SDK replaces that with an <image:…> reference to the attached PNG. Screening calls ask only present; search-loop calls ask present and where together.

Search-loop calls

  
For each class, the tile is searched in 25 sub-tiles of 160 px, each enlarged ×8 to 1,280 px. One call per pass. After a detection the box is inpainted, so the next image sent for that sub-tile has the symbol painted out. The pink rectangle is Jev's returned box, drawn here over the image. It was not part of what Jev saw.
