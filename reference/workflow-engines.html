Workflow engines cheat sheet

Make, Snakemake, DVC and a hand-written runner, compared on what matters for the map-digitizer pipeline. Sources are linked in each cell; versions are those checked on 2026-11-20.

At a glance

MakeSnakemakeDVCOwn runner
Stale when An input has a newer modification time. Contents are never read (verified, GNU Make 4.4.1). Any default trigger fires: code input mtime params software-env (snakemake --help, 9.27.2). A content hash of a dep, out or listed param changed; hashes kept in dvc.lock (docs). Whatever you implement.
Grid Pattern rules on file names. Wildcards in paths, e.g. {method}; values read off requested file names; expand() lists targets (docs). foreach (list) and matrix (combinations) generate one stage per item (docs). Loops you write.
Config value changes Only visible as "config file is newer". Re-runs rules whose params: changed. Re-runs stages listing that key under params. You track it.
Containers None built in. container: runs via Apptainer from docker:// URLs (docs). None built in. You call Docker.
Outputs Plain files. Plain files. Cached by DVC; dvc push to remote storage (docs). Plain files.
API response cache None of them. Lives in mapdig's own content-addressed cache.
